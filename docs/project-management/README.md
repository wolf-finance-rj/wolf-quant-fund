# Plano de gestão no GitHub

O GitHub Project é a fonte operacional de verdade; o plano técnico de 16 semanas é a referência estratégica.

## Status

Backlog (não refinada), Todo (refinada), In Progress (desenvolvimento), In Review (PR e validação), Done (aceite e merge). Use label `blocked` para impedimentos.

## Campos

Status, Priority, Área, Effort, Iteration, Assignees, Linked pull requests, Milestone. Evite manter Size e Effort simultaneamente.

## Milestones propostas

1. M1 — Foundation & Contracts (S1)
2. M2 — Data & Backtest MVP (S2)
3. M3 — Momentum Validation (S3–S4)
4. M4 — Multi-Strategy Portfolio (S5)
5. M5 — Experimental Closing (S6)
6. M6 — Release v1.0 (S7–S8)

## Revisão cruzada inicial

- Arquitetura ↔ Portfólio e Risco
- Dados ↔ Analytics
- Momentum ↔ Pairs

A pessoa que abre a PR não deve ser a única pessoa a validá-la. Aprovação técnica não substitui aprovação de governança financeira.
